# 程序化世界生成 Worldgen（abyssal-garden 管線分析）

> 狀態：研究筆記——Phase 4「具身於物理世界」的設計輸入，**尚未形成決策**；若未來採用任何一部分，屆時另立 ADR。
> 日期：2026-11-16
> 來源：[Noniv/abyssal-garden](https://github.com/Noniv/abyssal-garden)（MIT 授權）——單一 97 KB 的 HTML 檔，以 WebGPU 在瀏覽器裡程序化生成一整個海底世界：無圖片、無 3D 模型、無音效檔；地形、約兩百萬片海帶與植物、沉船、蝠鱝、魚群與整個音景，全部由程式碼在頁面載入時生成。可讀原始碼在其 repo 的 `source/src/`（world / math / main / shaders / audio / quality 共六個模組）。

## 0. 為什麼參考它

本專案的世界層（`GridWorld` 與 `FoodPatch` / `WaterSource` / `Shelter` / `Hazard`）目前由 TOML 情境檔手工描述（ADR-0008）。Phase 4 需要更豐富的環境；而在那之前，「同一套規則、不同種子 → 佈局不同但統計性質相似的世界」也直接服務 Phase 2 的族群執行器與 Phase 3 的學習心智（生物體不該在一張背熟的地圖上受測）。

abyssal-garden 是這個問題的一份完整、可讀、可跑的參考實作，而且工程價值觀與本專案同源：

| abyssal-garden | Unbodysoma 對應 |
|---|---|
| 固定種子（`20261110`）；每個生成系統獨立亂數流（`rseed(n)`） | ADR-0007 機率式行動選擇、ADR-0009 逐位元重播 |
| 世界是 `(程式碼, 種子)` 的純函數，零資產檔 | ADR-0001 核心零相依、情境即資料（ADR-0008） |
| 「導演式程序化」：全場景隨機，鏡頭路徑與觀景點周圍淨空 | 完成情境驗收（ROADMAP 各階段） |
| 載入失敗自動降一級品質重試、執行標記防呆 | HealthMonitor、critical 自動停止 |

## 1. 管線總覽

```
種子（每系統獨立亂數流）
   │
   ▼
密度場：FBM 值雜訊 + 手工幾何原語 + 平滑布林（smin/smax）   ← GPU compute shader
   │      （台地＝膠囊段、拱＝環面 SDF、隧道＝平滑差集、淨空區）
   ▼
清理：泛洪填連通性，刪除不接地的懸浮碎塊
   ▼
取面：Surface Nets（marching cubes 近親）→ 地形網格＋法線
   │
   ▼
撒點裝飾：以地形頂點為抽樣母體的拒絕採樣＋生態規則
   │      （坡度決定葉種、密度場決定群落、淨空區排除）
   ▼
場景物件：參數化數學網格（船＝剖面函數掃掠、鯨尾＝膠囊鏈 SDF）
   │
   ▼
動畫與光照：vertex shader 以（時間, 每實例種子）驅動；
           載入時烘焙天光體積（海帶會遮光）與整場陰影圖
```

七個階段的細節與檔案位置：

1. **決定論種子**（`math.js` 開頭）：mulberry32 亂數；`rseed(s)` 把每個生成系統（海帶、珊瑚、岩石、氣泡、魚群……）重設到 `base + s·7919` 的獨立流。改任一系統不影響其他系統的輸出——分系統除錯與局部修改的基礎。
2. **帶符號密度場**（`shaders.js` 的 `W_DENS`，compute shader）：在 512×80×512 體素網格（0.75 m 格距）上求密度：基底海床＝域扭曲（domain-warped）FBM 值雜訊；設計地形由 `world.js` 頂部的常數表驅動——`MESAS`（每座台地＝XZ 膠囊段＋半徑＋頂高＋懸垂＋腰身）、`ARCHES`（環面 SDF）、`HOLES`（以 smin 差集挖出的隧道）、`CLEARS`（淨空區，保護景點不被岩石覆蓋）。所有形體以多項式平滑布林 `smin`/`smax` 融合，因此看起來是一整塊岩盤。
3. **連通性清理**（`main.js`）：從海床向上逐柱掃描，標記與海底相連的岩石；不連通者視為懸浮碎屑，翻轉為水。程序化噪聲常見的「空氣中漂浮的岩屑」在此被系統性消除。
4. **取面**：naive Surface Nets（`math.js`）輸出頂點更少更平整的網格；法線由三線性插值密度場的中央差分求得。三角形再分裝進 16×16 的 XZ 剔除格。
5. **撒點裝飾**（`world.js` 主體）：直接以**地形頂點緩衝為抽樣母體**（隨機挑頂點＝天然在表面上），再用頂點法線做坡度測試與區域密度函數（`fbm` 熱點＋手工群落表）決定放什麼、放多少：15,000 株海帶候選、620,000 次地表覆蓋採樣、170,000 顆卵石、13,000 組海綿珊瑚候選。**生態規則**：法線 y＞0.7 才算地面、朝下長倒垂鬚、密度圖決定群落邊界。
6. **場景物件**：沉船＝參數化船體剖面 `pt(x, 相位)`（半船寬／吃水／舷弧三條曲線）沿龍骨掃掠，破洞以橢圓隨機挖除；鯨尾石雕＝膠囊鏈 SDF 再跑一次 Surface Nets；海綿＝車削輪廓＋FBM 凸塊；岩石＝icosphere 雜訊位移＋四個隨機平面切出斷裂面。
7. **動畫與光照**：所有動畫在 vertex shader 以（時間, 每實例種子）即時計算，CPU 零負荷——魚群是擺線參數式軌道＋切線朝向＋尾巴正弦擺動。載入時烘焙半解析度 3D 體積貼圖（開闊度＝廉價 AO、天光），**海帶把自己 的遮蔽量寫進天光烘焙**，因此海帶林下真的比較暗；整個靜態世界烘焙一張 4096² 陰影圖。

## 2. 對本專案的映射

| abyssal-garden 概念 | Unbodysoma 世界層對應 |
|---|---|
| 密度場原語＋平滑布林 | 地形與可通行性：`Hazard` 不再是手工矩形，而是密度場的等值線 |
| `CLEARS` 淨空區 | 保證 `Shelter` / `WaterSource` 周圍可生成、可抵達 |
| 生態撒點規則（坡度、群落密度） | `FoodPatch` / `WaterSource` 的密度函數化：從列舉座標變成採樣 |
| per-system 亂數流 | 世界生成納入 ADR-0007 / 0009 的可重現保證：`--seed` 同時決定生物體與世界 |
| 「導演式程序化」（鏡頭路徑淨空） | 完成情境的場地保證：關鍵行為（覓食、避險）的舞臺不被地形遮蔽 |
| 烘焙天光體積（植被遮光） | 未來若有能量／光照相關外感受，環境遮蔽的廉價近似 |

## 3. 不必等到 Phase 4：現在就能用的部分

**資源分布的密度函數化**只依賴「值雜訊＋拒絕採樣」，純 Python、零相依、二維即可：

- 現在：`grid_72h.toml` 的食物點、水源、危險區是手工座標。
- 之後可以是：`worldgen(seed, bounds) -> list[FoodPatch | WaterSource | Hazard | Shelter]`——FBM 密度場採樣出群落邊界，坡度／淨空規則保證可達性，輸出仍是現有的 dataclass，TOML 與 Python API 不變（符合 ADR-0008「兩種寫法等價」）。
- 立即受益者：Phase 2 族群執行器（每個個體配不同世界種子）、Phase 3 學習心智（避免地圖背誦）。

其餘（3D 密度場、Surface Nets、WGSL）屬 Phase 4，語言棧也不同（見 §5）。

## 4. Phase 4 與前端儀表板的借鏡

- **觀測儀表板**（[OBSERVABILITY.md](OBSERVABILITY.md) 規劃中的儀表板／重播）：abyssal-garden 的單檔 WebGPU 渲染器＋其 `dev.js`（一行腳本飛行運鏡＋逐幀 GPU 計時的基準模式）是「以固定路徑重播觀察模擬」的現成骨架——把畫面內容換成 `signals.csv` 驅動的狀態視覺化即可。
- **自適應品質**：其動態解析度以 GPU timestamp 實測毫秒、先降解析度再降繪製距離、結果持久化——對「儀表板在研究者的筆電上也要順」是有用的模式。

## 5. 邊界與不相容處

- **世界有界，不是無限**：固定體積網格（約 384×60×384 m）、外圍一圈岩壁收邊；所有撒點共用同一份全域地形頂點緩衝。要「無限串流世界」是架構重寫，不是參數調整。
- **語言棧**：TypeScript／WebGPU／瀏覽器 vs 本專案 Python 核心零相依（ADR-0001）。任何採用都是**重製**而非搬移；選用式前端相依有 ADR-0009（`[viz]`）的先例可循。
- **無物理、無實體系統**：其碰撞只服務相機球體（SDF 梯度推出）；對 Phase 4 的「真實能量成本與本體感覺」沒有直接貢獻。
- **保真度分級**：其地形是視覺導向的 L0（好看但無地質學依據）。本專案若要生成環境，也應比照 ARCHITECTURE 的保真度分級，從 L0 開始並標示。

## 6. 開放問題（不預設決策）

1. 世界生成放核心（`world/worldgen.py`，純 Python）還是選用相依（numpy／GPU）？——比照開放問題 1（Rust 核心）與 ADR-0009 的處理方式。
2. TOML 情境檔是否增加 `[worldgen]` 區段（種子＋密度場參數，取代手工座標）？——屆時另立 ADR，延續 ADR-0008 的嚴格驗證態度。
3. 生成結果是否寫入 `meta.json` 的可追溯鏈（種子＋參數＋SHA-256），讓一份執行紀錄能重建它來自哪個世界？
4. 獨立的程序化生成模板 repo（跨 Unbodysoma／遊戲／影片使用）與本專案的邊界如何切？
