# 0002. 模組只透過雙緩衝訊號匯流排溝通

- 狀態：已採用
- 日期：2026-10-17

## 背景

身體與心智的模組之間存在大量雙向耦合（評估 → 腎上腺素 → 心率 → 內感受 → 喚醒 → 評估）。如果模組彼此直接呼叫或共享物件：

- 結果會依賴執行順序，換個順序行為就不同；
- 替換一個模組需要修改所有依賴它的模組；
- 很難記錄「系統在某時刻的完整狀態」。

## 決定

- 模組之間**只能**透過命名的純量訊號溝通，訊號存在一條 `SignalBus` 上。
- 匯流排雙緩衝：讀取的是上一個 tick 提交的值，寫入進入暫存區，所有模組執行完後一次提交。
- 每個模組必須宣告 `reads` / `writes`；引擎強制「每個訊號只有一個寫入者」，啟動時檢查「每個被讀的訊號都有寫入者」；模組寫入未宣告的訊號會立即報錯。
- 心智層不得讀取 `soma.*`，只能讀取經由介面層轉換的 `intero.*`（見 [ARCHITECTURE.md](../ARCHITECTURE.md)）。

## 後果

- ✅ 執行順序無關、可重現。
- ✅ 模組可替換：只要讀寫同一組訊號。
- ✅ 匯流排快照即是系統的完整外部狀態，記錄與重播容易。
- ✅ 一個 tick 的傳導延遲在生物上是合理的（神經傳導本來就有延遲）。
- ❌ 只支援純量；向量或結構化資料（如記憶內容、影像）未來需要擴充訊號型別，屆時另立 ADR。
- ❌ 每條耦合都至少延遲一個 base tick；對 10 ms 的 base tick 而言可接受，但需要更緊密耦合的子系統（如心臟電生理）應在單一模組內部處理。
