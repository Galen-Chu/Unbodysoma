# 0011. 外部生理引擎：評估完成，暫不整合

- 狀態：已採用
- 日期：2026-11-16

## 背景

ROADMAP Phase 2 列出「外部生理引擎轉接器的可行性評估（Pulse / BioGears / FMI）」；SOMA.md §4 曾描繪長期路線：以轉接器把外部引擎包成 `Module`，自建部分集中在外部引擎沒有、但對心智重要的介面（內感受、神經調節、身心耦合）。

## 評估

- **Pulse Physiology Engine**（Kitware）：開源、經驗證的全身生理引擎，C++ 核心，覆蓋心血管／呼吸／藥理／創傷等場景。
- **BioGears**（Applied Research Associates）：開源全身生理引擎，C++ 核心，系統齊全。
- **FMI**（Modelica Association）：模型交換與共模擬的標準介面，可作為包裝層。
- **對接面**：本引擎的多速率固定步長（0.1–10 Hz）與兩引擎的步長（約 1/50–1/60 s 控制週期）數量級相容；訊號映射可行（血壓、血氧、代謝物均有對應）。
- **根本張力**：ADR-0009 要求快照重播**逐位元**一致；外部 C++ 引擎的數值行為跨平台／跨版本不在我們控制內，逐位元重播契約與運行時外部相依存在結構性衝突。此外外部引擎不提供內感受、評估與情感——本專案的差異化所在。

## 決定

- **暫不整合**任何外部生理引擎為運行時相依；核心維持零外部相依（ADR-0001）與逐位元可重播（ADR-0009）。
- L1 自建模型已達成 Phase 2 的曲線完成情境，繼續自建的邊際成本低於轉接器的長期維護成本。
- **保留 oracle 路線**：當 Phase 3+ 需要藥理／多器官干預的驗證生理時，以 FMI 或離線批次輸出把外部引擎當**測試預言機**（對照曲線來源），而非運行時組件——與文獻曲線驗收同一模式。
- 重訪條件：出現自建模型無法承載、且對心智層研究必要的生理現象（例如疾病、用藥動力學）時，另立 ADR。

## 後果

- ✅ 核心保持零相依、可重播、可移植；外部引擎的價值以驗收資料形式流入（REFERENCES.md 的曲線來源）。
- ✅ 心智層研究問題不受引擎選型干擾。
- ❌ 保真度上限受自建模型進度限制（L1→L2 漸進）；醫療級場景明確超出範圍（ETHICS.md）。
