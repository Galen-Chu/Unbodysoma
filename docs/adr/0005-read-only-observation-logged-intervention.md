# 0005. 觀察只讀，干預經由引擎並被記錄

- 狀態：已採用
- 日期：2026-10-18

## 背景

監控機制需要兩種能力：**看**（記錄、健康檢查、儀表板）和**動手**（固定訊號、拿掉模組，類似神經科學中的活化與抑制實驗）。如果兩者混在一起，例如讓觀察者直接寫匯流排，那麼「開著儀表板」和「關掉儀表板」可能得到不同的結果，實驗也無法重現。

## 決定

1. **觀察者只讀。** `Engine.observe(fn)` 的觀察者只會收到 `(t, bus)`，按約定不得寫入。`RunWriter`、`HealthMonitor`、`Recorder` 都遵守這個約定，並以測試驗證掛上它們不會改變結果。
2. **干預只能透過引擎 API 進行**：`clamp`、`lesion`、`cancel`。引擎在所有模組寫完之後、提交之前套用干預，因此干預一定會覆蓋模組輸出，而且與模組順序無關。
3. **所有干預都會被記錄**：排定、開始、結束、取消都會寫進 `engine.events`，`RunWriter` 會把它們（包括掛上之前就已發生的）寫進 `events.jsonl`。
4. **停止是唯一允許的觀察者副作用**：觀察者可以呼叫 `request_stop(reason)`，讓 `run` 在當前 tick 之後返回，並記錄 `engine.stopped`。
5. 干預是**實驗設定**，不是模擬狀態：`restore` 不會撤銷已排定的干預，以便從同一快照分出不同的實驗分支。

## 後果

- ✅ 任何監控工具都可以放心掛上，不會污染實驗。
- ✅ 每個干預實驗都可以從執行紀錄完整重建。
- ✅ 分支實驗（快照 → 干預 → 還原 → 取消）可以得到逐位元相同的對照組。
- ❌ 「觀察者不得寫入」目前只是約定：觀察者拿到的是完整的 `SignalBus`。若出現違規，可以改為傳入唯讀視圖。
- ❌ `clamp` 只影響讀取者，不會改變寫入模組的內部狀態；需要「改寫模組狀態」的實驗，應另外設計 API，而不是直接修改屬性。
