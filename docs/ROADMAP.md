# 路線圖 Roadmap

每個階段都以**可執行、可測試的情境**作為完成標準，而不是以「做完了哪些模組」。

## Phase 0 — 架構雛形（目前）

- [x] 引擎核心：多速率排程、雙緩衝訊號匯流排、模組契約檢查
- [x] 最小閉環生物體：威脅 → 評估 → 內分泌 → 心血管 → 內感受 → 情感 → 評估
- [x] Recorder 與 CSV 匯出
- [x] 行為回歸測試（恐懼反應、決定性）
- [x] 設計文件與 ADR
- [x] CI（lint + test + example）

**完成情境：** `examples/fear_response.py` —— 威脅出現時心率上升、逃跑、情感轉負，威脅消失後恢復。

## Phase 1 — 最小可行生物體

- [ ] 晝夜節律與睡眠（Borbély 雙歷程模型）：睡眠壓力、警覺度
- [ ] 體溫調節與行為性調節（找溫暖 / 涼爽的地方）
- [ ] 口渴與水分平衡
- [ ] 多行動競爭：逃跑 / 進食 / 飲水 / 休息 / 探索，以驅力與情感作為價值
- [ ] 簡單的 2D 網格世界：食物、水、危險、庇護所的位置
- [ ] 情境設定檔（TOML）：不寫 Python 也能組裝生物體與事件
- [x] 模組狀態宣告與快照 / 倒帶（ADR-0004）
- [x] 執行紀錄：`meta.json` · `signals.csv` · `events.jsonl`
- [x] 健康監控：範圍、持續時間、數值有限性規則；critical 時自動停止
- [x] 干預 API：`clamp` / `lesion` / `cancel`，並記錄進事件紀錄（ADR-0005）
- [x] 條件中斷：`run(until=…)`
- [ ] 快照寫入磁碟、從執行紀錄重播
- [ ] 即時儀表板：先接 Rerun，再做專屬的身心狀態視圖（見 [OBSERVABILITY.md](OBSERVABILITY.md) §7）
- [ ] 由模組宣告自動產生訊號表與依賴圖

**完成情境：** 一個生物體在網格世界中自主生活 72 小時（模擬時間），表現出合理的睡眠、進食、飲水與避險週期。

## Phase 2 — 生理保真度

- [ ] 核心子系統升級到 L1（附引用與參數表）
- [ ] 對照文獻反應曲線的驗證測試（例：葡萄糖耐受試驗、運動心率反應、急性壓力的皮質醇曲線）
- [ ] 呼吸系統與血氧
- [ ] 外部生理引擎轉接器的可行性評估（Pulse / BioGears / FMI）
- [ ] 效能分析，決定是否需要原生核心

**完成情境：** 至少三個子系統的典型反應曲線落在文獻容許範圍內，並有自動化測試把關。

## Phase 3 — 會學習的心智

- [ ] 神經調節訊號（`neuro.*`）
- [ ] 以「恆定誤差減少」為獎賞的強化學習
- [ ] 情節記憶：情緒強度調節記憶強度
- [ ] 古典與操作制約情境（例：學會害怕某個中性刺激，以及消退）
- [ ] 主動推論版本的模組，與模組化版本以相同行為測試比較
- [ ] 預測性調節（allostasis）：在需求出現前先行動

**完成情境：** 生物體能學會避開曾造成疼痛的地點，並在飢餓前預先尋找食物。

## Phase 4 — 具身於物理世界

- [ ] 接入物理引擎，運動有真實的能量成本與本體感覺
- [ ] 視覺等較豐富的外感受
- [ ] 肌肉疲勞與費力感

## Phase 5 — 自我與他人

- [ ] 自我模型：身體擁有感、自我 / 非自我區分
- [ ] 後設認知：對自身狀態的信心
- [ ] 受身體約束的語言表達層
- [ ] 多個生物體之間的互動

## 開放問題

這些問題會影響後續方向，歡迎在 Issues 中討論：

1. **核心語言：** Python 原型能撐到哪一個階段？何時、是否需要 Rust 核心？
2. **外部引擎 vs. 自建：** 生理層要深度整合 Pulse / BioGears，還是維持自建的輕量模型？
3. **統一原理：** 主動推論應該是最終的統一架構，還是多種機制之一？
4. **驗證標準：** 心智層的「正確」要如何定義？對照人類行為實驗資料？
5. **時間尺度：** 要支援「快轉」到數天、數年（發展、老化）嗎？是否需要變步長或事件驅動排程？
6. **使用者：** 主要受眾是研究者、教育者、遊戲 / 虛擬人開發者，還是以上皆是？
