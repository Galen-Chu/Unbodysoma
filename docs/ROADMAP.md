# 路線圖 Roadmap

每個階段都以**可執行、可測試的情境**作為完成標準，而不是以「做完了哪些模組」。

## Phase 0 — 架構雛形（目前）

- [x] 引擎核心：多速率排程、雙緩衝訊號匯流排、模組契約檢查
- [x] 最小閉環生物體：威脅 → 評估 → 內分泌 → 心血管 → 內感受 → 情感 → 評估
- [x] Recorder 與 CSV 匯出
- [x] 行為回歸測試（恐懼反應、決定性）
- [x] 設計文件與 ADR
- [x] CI（lint + test + example）

**完成情境：** `examples/fear_response.py` —— 威脅出現時心率上升、逃跑、情感轉負，威脅消失後恢復。

## Phase 1 — 最小可行生物體（完成，2026-10-25）

- [x] 晝夜節律與睡眠（Borbély 雙歷程模型）：睡眠壓力、晝夜節律、睡意、被叫醒後再入睡、睡眠剝奪
- [x] 體溫調節（產熱、散熱、顫抖、流汗）與行為性調節（冷熱時回庇護所）
- [x] 口渴與水分平衡（流汗耗水，與體溫調節互相牽制）
- [x] 閉合飢餓迴路：感覺到食物 → 進食 → 能量攝取 → 飽足（逃跑優先於進食）
- [x] 多行動競爭：閒置 / 逃跑 / 進食 / 探索 / 飲水 / 找水 / 回庇護所 / 睡眠，以驅力與評估作為效用（ADR-0007）
- [x] 2D 網格世界：會耗盡與再生的食物點、固定與定時（含每日重複）的危險區、移動與導航
- [x] 網格世界中的水源、庇護所（隔熱、擋住危險、記得回家的路）與晝夜溫差
- [x] 參數與訊號的宣告式規格：範圍驗證、寫入執行紀錄、衍生健康規則（ADR-0006）
- [x] 預設生物體的參數覆寫：`build_minimal_human(overrides=…)`
- [x] 情境設定檔（TOML）與命令列 `python -m unbodysoma run / validate`（ADR-0008）
- [x] 模組狀態宣告與快照 / 倒帶（ADR-0004）
- [x] 執行紀錄：`meta.json` · `signals.csv` · `events.jsonl`
- [x] 健康監控：範圍、持續時間、數值有限性規則；critical 時自動停止
- [x] 干預 API：`clamp` / `lesion` / `cancel`，並記錄進事件紀錄（ADR-0005）
- [x] 條件中斷：`run(until=…)`
- [x] 快照寫入磁碟、從執行紀錄重播並逐位元驗證（ADR-0009）
- [x] Rerun 即時檢視轉接器（選用相依 `unbodysoma[viz]`）
- [ ] 專屬的身心狀態儀表板（人體狀態圖、情感平面；見 [OBSERVABILITY.md](OBSERVABILITY.md) §7）→ 移至 Phase 2
- [x] 由規格自動產生訊號表與參數表（`python -m unbodysoma.catalog`，CI 檢查是否過時）
- [x] 由模組宣告自動產生訊號依賴圖（[SIGNAL_GRAPH.md](SIGNAL_GRAPH.md)）
- [x] 工程品質：觀察者唯讀、mypy strict、版本號單一來源、換行符號正規化
- [x] 機率式行動選擇：以速率表示的 softmax 切換，溫度為可調特質（ADR-0007）
- [x] 結構化雜訊工具（Ornstein–Uhlenbeck），心率變異（HRV）與情緒的自發波動
- [x] 分析工具：HRV 指標、熵比、眾數放大比、行為事件與每日統計
- [x] 效能：多日模擬的引擎最佳化（結果逐位元不變）

**完成情境：** 一個生物體在網格世界中自主生活 72 小時（模擬時間），表現出合理的睡眠、進食、飲水與避險週期。

**達成（2026-10-25）：** `scenarios/grid_72h.toml` 與 `tests/test_phase1.py` 驗收：每晚一次 7–8 小時、全部在庇護所內的睡眠；每天 3–6 餐且使用多個食物點；每天至少一次飲水；夜間約 8 °C、午後約 23 °C 的氣候下核心體溫維持在 36.4–37.1 °C；掠食者出現時逃跑、處於嚴重危險的時間 < 0.5 %；沒有任何生理警報。

**留意：** 在部分種子中，清晨又餓、又渴、又冷地出門吃早餐時，會出現數分鐘的強烈負面情緒（`prolonged_negative_valence`）。這是情感模型以線性加總合成多個需求所致，已列為待討論問題（[PSYCHE.md](PSYCHE.md) §5），驗收時限制其時間比例 < 2 %。

## Phase 2 — 生理保真度

- [x] 代謝升級：血糖-胰島素核心採 Bergman（1979）最小模型＋Dalla Man（2006）雙區間腸道；ADA（2021）曲線驗收（`tests/test_metabolism_l1.py`）— 2026-11-16；能量池仍 L0，其完整整合待後續
- [x] 內分泌升級：皮質醇路徑採 HPA 延遲＋甦醒反應（CAR）＋負回饋（Dickerson & Kemeny 2004、Clow 等 2010 曲線驗收，`tests/test_endocrine_l1.py`）— 2026-11-16；腎上腺素仍 L0（秒級動力學）
- [x] 心血管升級：雙路徑速率動力學（神經快路徑＋代謝慢路徑）＋年齡天花板（Whipp & Wasserman 1972、Tanaka 2001、Cole 1999 曲線驗收，`tests/test_cardio_l1.py`）— 2026-11-16；血壓／心輸出量仍無
- [x] 專屬的身心狀態儀表板：`python -m unbodysoma dashboard <run>` 產生自足式 HTML（統計表、全訊號火花線、情感平面軌跡；決定論輸出）— 2026-11-16，`observe/dashboard.py`
- [x] 情感的多需求合成方式：以 `grid_72h` 對照實驗決定採**飽和聯集**（多需求負面情緒 0.37 %→0.17 %，單一威脅反應不變）— 2026-11-16，`Affect.need_saturation`、`tests/test_affect_saturation.py`（見 [PSYCHE.md](PSYCHE.md) §5）

- [x] 核心子系統升級到 L1（附引用與參數表）— 心血管／內分泌／代謝／呼吸四個子系統，見 §2 各節
- [x] 對照文獻反應曲線的驗證測試（例：葡萄糖耐受試驗、運動心率反應、急性壓力的皮質醇曲線）— `tests/test_{metabolism,endocrine,cardio,pulmonary}_l1.py` 共 23 項
- [x] 呼吸系統與血氧 — `soma/pulmonary.py`（Cretikos 2008、O'Driscoll 2008 驗收）
- [x] 外部生理引擎轉接器的可行性評估（Pulse / BioGears / FMI）— 評估完成，暫不整合、保留 oracle 路線（[ADR-0011](adr/0011-external-physiology-engines-deferred.md)）
- [x] 效能分析，決定是否需要原生核心 — 量測 1741× 實時，暫不需要（[ADR-0012](adr/0012-native-core-not-needed-yet.md)）
- [x] 參數規格與族群定義檔：從族群分布抽樣個體（見 [VARIABILITY.md](VARIABILITY.md)）— `population.py` 的 `POPULATION_SPEC`＋`sample_individual`（截斷常態、範圍取自參數規格）
- [x] 族群執行器與分布層級的驗收指標（眾數放大比、熵比、HRV 指標）— `run_population`＋`population_action_metrics`（動作分布的熵比與眾數放大比、每人 RMSSD）、`examples/population.py`
- [x] 心率變異（HRV）的頻譜結構 — `metrics.band_powers`／`lf_hf_ratio`（Task Force 1996 的 LF/HF 帶，Goertzel），靜止時 HF 主導、交感活化時 HF 崩落（`tests/test_hrv_spectral.py`）

**完成情境：** 至少三個子系統的典型反應曲線落在文獻容許範圍內，並有自動化測試把關。

**達成（2026-11-16）：** 心血管／內分泌／代謝／呼吸四個子系統的典型反應曲線均落入文獻容許範圍並有自動化測試把關；族群執行器與分布級驗收指標就位。Phase 2 完成情境與全部清單項目收尾——遺留的深化項目（能量池整合、RSA-呼吸耦合、血壓／心輸出量、L2 保真度等）已歸檔至 [BACKLOG.md](BACKLOG.md) §1。

## Phase 3 — 身心深化 I：微生物級——非聯結學習與獎賞基礎

> 2026-11-18 起軌道調整（[ADR-0013](adr/0013-subsystem-focus-track.md)）：階段沿生物能力帶組織，每一階段都以**可對照文獻行為數據的驗收測試**為完成標準（與 Phase 2 的生理曲線驗收同一模式）。載體維持人體級 soma，不降級；身體子系統依心智實驗需求從 [BACKLOG.md](BACKLOG.md) §1 拉入深化。

- [ ] 痛覺 Nociception：組織損傷 → 疼痛訊號＋迴避（制約實驗的非制約刺激）
- [ ] 神經調節訊號（`neuro.*`）最小模型：多巴胺／血清素／正腎上腺素三軸——獎賞、情緒色調、警覺——對映到現有迴路（設計輸入見 [BACKLOG.md](BACKLOG.md) §5）
- [ ] 非聯結學習：**習慣化與敏感化**（含自發恢復的時間過程）
- [ ] 獎賞規格：以「恆定誤差減少」為獎賞；能量池與血糖-胰島素整合（reserve＝淨葡萄糖平衡）——獎賞訊號的直接前置
- [ ] 驗收儀器：族群平行執行（學習曲線的個體間分布，VARIABILITY 指標的第一次學習版實戰）

**完成情境：** 重複中性刺激下，朝向／驚嚇反應隨重複次數衰減並在休息後自發恢復，衰減與恢復的時間過程落在文獻容許範圍；反覆傷害性刺激造成敏感化。對照標的：線蟲與海兔的習慣化曲線（[REFERENCES.md](REFERENCES.md) 學習與制約節）、大腸桿菌趨化的偏置隨機漫步（現有導航 wander 的文獻對照）。

## Phase 4 — 身心深化 II：無脊椎動物級——聯結學習與記憶

- [ ] 古典制約：Rescorla–Wagner 動力學——獲得、消弱、自發恢復、阻斷（Kamin）
- [ ] 操作制約：行為 → 結果的聯結
- [ ] 情節式記憶表徵：情緒強度調節記憶強度（向量嵌入 vs 符號事件 vs 混合，見 BACKLOG §5）
- [ ] 制約情境檔格式：`[[world.stimulus]]` 事件類型（中性刺激與威脅／食物的配對時序）
- [ ] 場所趨避：學會避開曾造成疼痛的地點（grid／sanctuary 世界作為實驗場）

**完成情境：** 中性刺激與威脅配對後引發防禦反應（獲得），單獨呈現時反應隨次數衰減（消弱），隔段時間後部分恢復（自發恢復）；已建立的線索會阻斷新線索的學習（阻斷）。獲得／消弱曲線落在 Rescorla（1988）等文獻容許範圍，有自動化測試把關。

## Phase 5 — 身心深化 III：脊椎動物級——注意、預測與規劃

- [ ] 注意力分配（M3 補完）：模組競爭進入工作空間的候選架構（全域工作空間理論）
- [ ] 預測性調節（allostasis）：預期未來身體狀態，在需求出現前先行動（飢餓前預先覓食、危險時段前先回庇護所）
- [ ] 主動推論版本的模組，與模組化版本以相同行為測試比較（PSYCHE.md §3 的 A→B 演進，比較前重新檢視並另立 ADR）

**完成情境：** 生物體在飢餓發生前預先覓食、在慣常的掠食者時段前離開開闊地；對照覓食理論（Charnov 1976，邊際值定理）與情景式記憶的行為數據。

## Phase 6 — 人類級：自我與他人

- [ ] 自我模型：身體擁有感、自我 / 非自我區分
- [ ] 後設認知：對自身狀態的信心
- [ ] 受身體約束的語言表達層

## 支撐軌道（不佔階段編號；依心智實驗需求拉入）

- **世界與具身**（原 Phase 4「具身於物理世界」）：物理引擎、豐富外感受、肌肉疲勞與本體感覺。程序化環境生成的設計輸入見 [WORLDGEN.md](WORLDGEN.md)。
- **身體子系統持續深化**：血壓／心輸出量（Guyton）、多區間體溫、光照節律、CO₂ 化學感受器等，依各階段實驗需求排入（[BACKLOG.md](BACKLOG.md) §1）。
- **生態整合**：M1「N 個體 × M 世界」自里程碑降級為驗證儀器（ADR-0013）；世界 provenance、標本適配等見 BACKLOG §4。

## 開放問題

這些問題會影響後續方向，歡迎在 Issues 中討論：

1. ~~**核心語言：** Python 原型能撐到哪一個階段？何時、是否需要 Rust 核心？~~ → **已回答（[ADR-0012](adr/0012-native-core-not-needed-yet.md)）**：暫不需要；重訪觸發條件明列於 ADR。
2. ~~**外部引擎 vs. 自建：** 生理層要深度整合 Pulse / BioGears，還是維持自建的輕量模型？~~ → **已回答（[ADR-0011](adr/0011-external-physiology-engines-deferred.md)）**：暫不整合，保留測試預言機路線。
3. **統一原理：** 主動推論應該是最終的統一架構，還是多種機制之一？
4. **驗證標準：** 心智層的「正確」要如何定義？對照人類行為實驗資料？
5. **時間尺度：** 要支援「快轉」到數天、數年（發展、老化）嗎？是否需要變步長或事件驅動排程？
6. **使用者：** 主要受眾是研究者、教育者、遊戲 / 虛擬人開發者，還是以上皆是？
7. **變異與族群：** 預設模擬哪一個族群？哪些參數要從常數改成分布，優先順序如何決定？（見 [VARIABILITY.md](VARIABILITY.md) §10）
